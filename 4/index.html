A2

In this section, we aim to recover the parameters of the transformation between the two images. We represent this as a homography: p’ = Hp where H is a 3x3 matrix with 8 degrees of freedom, and p is a 3x1 matrix of x, y, and 1 and p’ is a 3x1 matrix of wx’, wy’, and w according to the definitions of homographic transforms. The bottom right corner of H is a scaling factor and is set equal to 1. To solve for the elements of H, we first create 3 systems of equations, resulting in ax + by + c − gxx′ − hyx′ = x′ and dx + ey + f − gxy′ − hyy′ = y′, and reformatting this in matrix forms gives the form of Ah = b with h as the column vector of H’s unknowns and b as [x’, y’]. Using this form, if we stack A to include n points (2n rows respectively with different values for x, y and x’, y’) we get in return b with 2n rows with corresponding (x’, y’) sequences. To get the values of the matrix H that is most accurate for such a transformation, we minimize ||Ah - b|| where Ah is the computed value of the transformation and b is the real second point values.

To this end, we first create two matrices, im1_pts and im2_pts, which contain n corresponding point pairs of p and p’, each with the corresponding (x, y) as row. Formatting the data, we should get the best approximation of H that matches the homographic transformation.

A3

In this section, we need to implement warping using two different interpolation styles: nearest neighbor and bilinear interpolation.

In the previous part, we calculated the matrix H that warps im1 to im2, but in this section we need to use inverse warping. The reason for this is simple. The matrix H that we calculated maps a source pixel to a destination pixel. However, if H stretches an image, neighboring pixels in our source image get pulled apart and holes remain in the gaps between them with no mapping. Similarly, if H shrinks an image, neighboring pixels can instead rewrite one another. As such, we use a technique called inverse warping that instead asks: “where in the source image is this target pixel from.” Doing this allows us to instead find out for every target pixel, what pixels in source it came from, and perform our particular interpolation program on the source image to rewrite its warped value.

One thing to note is that we use a bounding box in this section. We find in the source image, where the 4 corners map onto the target image, create a rectangle over the mapped corners and perform the inverse warping procedure to derive its new value from interpolation, and continue on.

Our project here has two types of interpolation: nearest neighbor and bilinear interpolation. Nearest neighbor interpolation simply rounds coordinates to the nearest pixel value. Bilinear interpolation on the other hand, maps the target pixel to a source position, weighs the 4 nearest pixels in all directions (its corners) and computes a weighted sum of their pixel values. The formula for this mapping is w₁₁ = (1 − x)(1 − y)

w₁₂ = (1 − x)y

w₂₁ = x(1 − y)

w₂₂ = xy

f(x, y) ≈ w₁₁·f(Q₁₁) + w₁₂·f(Q₁₂) + w₂₁·f(Q₂₁) + w₂₂·f(Q₂₂)

Finally, once we map back we do the final steps. First we compute a mask that ensures that the mapped positions are in bounds. Then we pull the RGB values of the valid points (and 4 corners if bilinear), and create a blank output image for final usage.

We can test this method on 3 different rectification images. For this process, since we don’t have an actual target image to compute from, we can arbitrarily set the value of the reference box to the size of the image we wish for it to reach, keeping the aspect ratio of the object. Comparing the two methods, we can see the difference most clearly in the close-ups of the rectified objects. In the map close-up, nearest neighbor makes the small text and the lines of the floor plan look jagged and broken, since every output pixel copies a single source pixel. Bilinear on the other hand, averages the 4 nearest pixels, so the same text and lines come out smooth, although the result looks slightly softer overall. The difference is smaller on the sign, where the letters are large, but the edges of the letters are still a bit stair-stepped with nearest neighbor.

In terms of speed, nearest neighbor is faster because it only needs one lookup per output pixel, while bilinear needs 4 lookups and a weighted sum. On our images, bilinear took about 2 to 3 times as long as nearest neighbor (for example, 0.16s vs 0.48s on the exam scene). Since both run in under a second and bilinear gives better quality, we use bilinear for the mosaics in the next section.

A4

In this section, we need to merge our images together to create a final mosaic. Here, I choose to keep the left image unwarped and warp the right image into its frame. The first step is to build the final canvas that contains everything by comparing the height and width of the warped image and the reference image (left is reference and right is warped). The reference image has x pixels ranging from [ref_x, ref_x + ref_w] and y pixels ranging from [ref_y, ref_y + ref_h]. Conversely, in reference image coordinates, the warped image’s x pixels range from [warped_x, warped_x + warped_w] and y pixels range from [warped_y, warped_y + warped_h]. Going by reference image coordinates, the reference image’s top left corner is in (0, 0) so ref_x, ref_y = 0. Conversely, the warped image’s top left corner in reference coordinates is (warped_x, warped_y). As such, to get the mosaic up and ready, we need to compute the values of left, right, top, and bottom such that:

left = min(ref_x, warped_x)

top = min(ref_y, warped_y)

right = max(ref_x + ref_w, warped_x + warped_w)

bottom = max(ref_y + ref_h, warped_y + warped_h)

Setting:

mosaic_w = right - left

mosaic_h = bottom - top

Now, since we can’t work with negative values, we have to shift everything so that mosaic’s top left is (0,0) now. In other words, we are shifting from reference image coordinates to mosaic coordinates. We do this by calculating:

ref_x, ref_y = ref_x - left, ref_y - top

warped_x, warped_y = warped_x - left, warped_y - top

Now, we have dimensions for our final mosaic. We then place the warped image and reference image on top of the mosaic and initiate the laplacian stack blending process. We can do this by re-referencing proj2 and creating a laplacian stack to slowly blend the two images together. Here, the reference image is a and the warped image is b in blend_levels. For the mask, we use a distance transform on each image to find how far each pixel is from that image’s edge, and set the mask to 1 where the reference image is farther from its edge than the warped image. This way, the seam is where both images are equally far from their edges.

B.1

In this section we are performing the adaptive non-maximal suppression algorithm. So what exactly motivates this algorithm? When we have numerous Harris Corners, we don’t want our set of matching features to be too overpopulated in specific areas (such as certain textures, grasping more corners). As such, the concept of ANMS is to maintain only the set of Harris corners with large suppression radii. In other words, we pick (in this case the top 500) corners whose harmonic mean of eigenvalues is more robust than all others in their neighborhood and select the interest features for which the minimum radius to a stronger corner (f(xi) < c * f(xj)) is the largest. In this manner, we get Harris corners that are more spread out and more defining of the image itself. B.2

In this section, we wish to perform feature extraction. To that end, using the interest points detected earlier with ANMS, centered on each interest point, we take a 40x40 window surrounding the pixel. From there, we utilize a Gaussian blur, which allows for the resulting patch to have more similar values to one another, and sample every 5th pixel in every direction in order to obtain a more representative 8x8 pixel patch. From there, we bias/gain normalize the patch and prepare the descriptor for comparison later.

B.4

In this section we now use the RANSAC algorithm to compute a robust homography that utilizes the rough feature matching process in the previous part. The algorithm is simple. We first pick 4 random matches from our computed matched descriptors. Using our part A’s computeH, we compute a homography and calculate the error between the changed image’s matched and morphed interest points. Using this, we calculate the number of “inliers,” which is defined as a point such that the difference between the morphed and matched points is a small value epsilon (which is generally 1-3 pixels). From there, after repeating this process, we select the homography that creates the greatest amount of inliers and recompute the homography using only the inliers instead of the original best 4 point pairs.
