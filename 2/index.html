Part 1.1: Convolutions from Scratch

The first step in a convolution is to flip the kernel (without the flip it would be cross-correlation, which matters for asymmetric kernels like Dx). From there, you want to slide the kernel across all pixels in the image, utilizing elementwise products to compute a single final value for the new pixel.

Of importance is the notion of mode="same" or mode="full". Both of these methods require first zero padding our input image such that our kernel can safely be centered on every pixel and compute the same required elementwise product operations without causing an out of bounds error. I.e. a 3x3 kernel centered on the top left pixel needs an extra margin of 2 pixels padding on both the top and left (and since it is symmetric for the bottom right pixel, on the bottom and right as well). Using this logic, we can initialize our mode="full" output shape to be (height + kh - 1, width + kw -1) accounting for top and bottom where kh and kw is equal to the kernel’s shape.

From there, mode="full" and mode="same" differ. mode="full" is every position where the kernel overlaps the image while mode="same" crops the output image to be the same dimensions as the original image.

One more thing of note is the differences in convolve4 and convolve2. Convolve4 uses 4 nested for loops while convolve2 uses 2 along with a numpy elementwise product of two matrices, which is faster for the 9x9 box (656 ms vs 6874 ms). For Dx and Dy, convolve4 is actually faster (235 ms vs 621 ms), since the kernel only has 2 entries and convolve2 pays numpy’s overhead at every pixel. scipy.signal.convolve2d is far faster than both (29 ms for the box, 2 ms for Dx and Dy). Both my functions and scipy (boundary="fill") pad with zeros, so the outputs match, including the darker border on the box-filtered image.

To define our kernels, we simply use a box kernel which is just of shape (k, k) divided by k^2 and the finite difference operators Dx = [1, -1] and Dy = Dx.T

def getBox(k):
    # kxk box filter, each entry is 1/k^2
    box_filter = np.ones((k, k)) / (k * k)
    return box_filter

def convolve4(img, kernel, mode="same"):
    # flip the kernel as required
    kernel = kernel[::-1, ::-1]
    kh, kw = kernel.shape
    height, width = img.shape
    output_height = height + kh - 1
    output_width = width + kw - 1
    output = np.zeros((output_height, output_width))
    # pad kh - 1 and kw - 1 zeros on every side
    img = np.pad(img, ((kh - 1, kh - 1), (kw - 1, kw - 1)), mode="constant", constant_values=0)
    for i in range(output_height):
        for j in range(output_width):
            for ki in range(kh):
                for kj in range(kw):
                    output[i, j] += img[i + ki, j + kj] * kernel[ki, kj]
    if mode == "full":
        return output
    top = (kh - 1) // 2
    left = (kw - 1) // 2
    return output[top:top + height, left:left + width]

def convolve2(img, kernel, mode="same"):
    kernel = kernel[::-1, ::-1]
    kh, kw = kernel.shape
    height, width = img.shape
    output_height = height + kh - 1
    output_width = width + kw - 1
    output = np.zeros((output_height, output_width))
    img = np.pad(img, ((kh - 1, kh - 1), (kw - 1, kw - 1)), mode="constant", constant_values=0)
    for i in range(output_height):
        for j in range(output_width):
            window = img[i:i + kh, j:j + kw]
            output[i, j] = np.sum(window * kernel)
    if mode == "full":
        return output
    top = (kh - 1) // 2
    left = (kw - 1) // 2
    return output[top:top + height, left:left + width]

Part 1.2: Finite Difference Operator

Here in 1.2 we have the same convolution of an image with finite difference operator kernels. We calculate the gradient magnitude image by utilizing the formula gradient_i = np.sqrt(I_Dx ** 2 + I_Dy ** 2) where I_Dx, I_Dy is the value of the cameraman’s pixel i after convolution with the finite difference operators and gradient_i is the value of the gradient magnitude image at pixel i.

From there, we implement a binarization, where we basically set a cutoff value for the pixel images in gradient_i and black out the pixels that are below a threshold t. Part 1.3: Derivative of Gaussian (DoG) Filter

This procedure here of first blurring with a gaussian (low pass filter, 13x13, σ = 2) then convolving the resulting image with a finite difference operator provides different results than simply using only the finite difference operator. Most prominent, is that immediately, the edges and lines “detected” are much smoother. Furthermore, there seems to be less occurrences of noise in the image, since the gaussian removes the high frequency noise that the derivative would otherwise amplify, providing a better holistic result. As a consequence however, the blur spreads each edge over several pixels, so the intensities of the lines detected are smaller and the edges thicker, and thus the binarization threshold is much smaller (0.08), but overall I believe this is a better result!

Part 2.1: Image Sharpening

Unsharp masking as a concept is actually pretty simple. When we blur an image with a gaussian, we “smoothen” it and remove high detail features (high frequencies). As such, if we subtract the blurred image from the original image, we isolate the high detail (high frequency) features only of the image. As such, deriving from this is the image sharpening process, where we use a scaling factor, alpha, to add varying amounts of high detail features to the original image.

# f + a (f - f ∗ G) = f ∗ [(1 + a) · unit - a · G]
unit = np.zeros_like(G)
unit[6][6] = 1
unsharp_mask = lambda a: (1 + a) * unit - a * G

Part 2.2: Hybrid Images

Hybrid images take advantage of the fact that we see high frequencies up close and only low frequencies from far away. I low-pass one image with a gaussian, high-pass the other with an impulse minus a gaussian (the same idea as the high frequency image in 2.1), and add them together. Every pair is first aligned by clicking two points in each image, then resized to 500 pixels wide so the same σ means the same thing on every pair.

The cutoff of each filter according to the paper is the frequency where its gain drops to 1/2. I picked the σ values by experimenting: for each pair I ran a grid of low and high σ values and looked at every result at full size and shrunk down to about a quarter size. σ_low always has to be larger than σ_high, otherwise the two frequency bands overlap and you see both images at every distance.

def gaussian(s):
    ksize = 2 * int(np.ceil(3 * s)) + 1
    G1D = cv2.getGaussianKernel(ksize=ksize, sigma=s)
    return G1D @ G1D.T

def laplacian(s):
    G = gaussian(s)
    unit = np.zeros_like(G)
    unit[G.shape[0] // 2][G.shape[1] // 2] = 1
    return unit - G

low_part = conv_color(low, gaussian(low_s))
high_part = conv_color(high, laplacian(high_s))
hybrid = np.clip(low_part + high_part, 0, 1)

Part 2.3: Gaussian and Laplacian Stacks

In lecture, a Gaussian pyramid is built by repeatedly blurring an image with a Gaussian and then downsampling it to half its size, so each level is a smaller, blurrier version of the one before. A Gaussian stack holds the same information, but every level stays at the original resolution and just gets progressively blurrier. Because the stack never shrinks, I can't rely on the same small filter blurring more at each level, so I use a different σ at each level instead. The lecture notes that the filter size should double for each half-size reduction, so level i is the original image blurred with σ = 2i−1, giving σ = 1, 2, 4, 8, 16, 32.

def get_gaussian_stack(img, n):
    # G0 = img, Gi = img blurred with sigma 2 ** (i - 1)
    stack = [img]
    for i in range(1, n):
        stack.append(conv_color(img, gaussian(2 ** (i - 1))))
    return stack

def get_laplacian_stack(img, n):
    g_stack = get_gaussian_stack(img, n)
    stack = []
    for i in range(n - 1):
        stack.append(g_stack[i] - g_stack[i + 1])
    stack.append(g_stack[-1])
    return stack

The Gaussian stack gets progressively blurrier. On the apple, the first levels lose the fine speckle on the skin, the middle levels lose the shading details, and by σ = 32 only the overall red shape and the background colors are left. Each Laplacian level is the difference between two neighboring Gaussian levels, so it holds one band of frequencies. Level 0 has the finest texture (the orange peel's dimples, the apple's speckle), the middle levels hold edges and shading, and the last level is the blurriest Gaussian, which holds the overall color. Because the differences telescope, adding all the Laplacian levels back up reproduces the original image exactly. The Laplacian images are rescaled for display since they contain negative values.

Part 2.4: Multiresolution Blending

If you blend two images with one hard mask, you get a visible seam. If you blur the mask a lot, you get a ghosted double image near the seam instead. The fix is to blend each frequency band separately with a mask blurred to match that band. I build the Laplacian stacks of both images and a Gaussian stack of the mask, then at each level compute S_i * L_A + (1 − S_i) * L_B, and add up all the blended levels. The fine levels use a nearly sharp mask, so fine detail switches over quickly at the seam. The coarse levels use a very blurred mask, so the overall colors fade gradually.

a_lap = get_laplacian_stack(a, n)
b_lap = get_laplacian_stack(b, n)
m_stack = get_gaussian_stack(mask, n)
a_levels = [m * l for m, l in zip(m_stack, a_lap)]
b_levels = [(1 - m) * l for m, l in zip(m_stack, b_lap)]
blend = [x + y for x, y in zip(a_levels, b_levels)]

What I Learned

The most important thing I learned is probably the method of merging two images with laplacian stacks. Overall, seeing clearly the exact breakdown of the process of how at every single level of the stack, the mask is applied to that level and then all the levels are added back up together, really helped me understand why the blend looks so smooth instead of just having a hard line down the middle.
